# Packaging Tally

What is built, what is verified, and what still needs a human with a signing
identity. Being precise about that boundary matters more than the instructions.

## Status

| Target | Builds | Runs | Verified how |
|---|---|---|---|
| **macOS** (`.app`) | ✅ | ✅ | universal binary (arm64 + x86_64), valid `Info.plist`, recognized by Launch Services, launched |
| **iOS Simulator** | ✅ | ✅ | `xcodebuild` succeeded, installed and launched on an iPhone simulator, screenshotted rendering the real dashboard |
| **iOS device** | ✅ (unsigned) | ⚠️ untested | the framework builds an `ios-arm64` slice; running on hardware needs a signing team |
| **Android** | ✅ | ⚠️ untested | `.aar` and APK assemble; no device or emulator was run |
| **Web** (wasm) | ✅ | ✅ | `GOOS=js GOARCH=wasm go build` + the gophics demo page |

Nothing here has been through App Store or Play review. The signing, provisioning
and store-listing steps below are written from the platform requirements, not from
a submission that has actually happened.

## Icon

The icon is drawn by gophics itself (`examples/tally/icon`), so it is source
rather than a binary blob and regenerates at every size from one description:

```sh
go run ./icon -out .            # icon.png, icon.iconset/, iOS + Android assets
iconutil -c icns icon.iconset -o Tally.icns
```

## macOS

```sh
./package/macos.sh              # build/Tally.app (universal, unsigned)
./package/macos.sh --open       # and launch it
```

To distribute outside the store, sign and notarize:

```sh
CODESIGN_ID="Developer ID Application: NAME (TEAMID)" ./package/macos.sh
xcrun notarytool submit build/Tally.app --keychain-profile NOTARY --wait
xcrun stapler staple build/Tally.app
```

For the **Mac App Store** the requirements differ: a `3rd Party Mac Developer
Application` identity, a provisioning profile embedded at
`Contents/embedded.provisionprofile`, and the App Sandbox entitlement. Tally needs
exactly one sandbox exception — user-selected files, because the whole app is
"open the ledger you chose":

```xml
<key>com.apple.security.app-sandbox</key><true/>
<key>com.apple.security.files.user-selected.read-write</key><true/>
```

Nothing else: no network, no camera, no location. A finance app that asks for
nothing is both easier to review and easier to trust.

## iOS

```sh
./package/ios.sh                # bind + generate + build for the simulator
./package/ios.sh --run          # and install/launch it
```

For a device or the App Store, open `ios/Tally.xcodeproj` and set a team, or:

```sh
xcodebuild -project ios/Tally.xcodeproj -scheme Tally \
  -sdk iphoneos -configuration Release \
  DEVELOPMENT_TEAM=TEAMID archive -archivePath build/Tally.xcarchive
xcodebuild -exportArchive -archivePath build/Tally.xcarchive \
  -exportOptionsPlist package/ExportOptions.plist -exportPath build/ipa
```

The Xcode project is generated by `xcodegen` from `ios/project.yml` and is not
committed — a generated `pbxproj` is a merge-conflict machine.

## Android

```sh
./package/android.sh            # bind + assembleDebug
./package/android.sh --release  # assembleRelease (needs a keystore)
```

Release signing expects the usual four properties (`storeFile`, `storePassword`,
`keyAlias`, `keyPassword`) in `~/.gradle/gradle.properties` or the environment;
they are deliberately not in the repo.

## What a reviewer will ask

- **Privacy**: Tally collects nothing and has no network code. The privacy
  manifest and App Store answers should say "no data collected" — and that is
  true, not aspirational: the binary has no networking in it.
- **Account deletion**: not applicable; there are no accounts.
- **Purpose strings**: none needed. Tally requests no camera, microphone,
  location, contacts or notification permission.
- **Accessibility**: the semantics tree is exposed to VoiceOver and TalkBack
  through the bind surface (`A11y*`). This has not been tested with VoiceOver on
  a device.

## Toolchain notes (found the hard way)

- **Android needs JDK 21.** Gradle 8.9 cannot read classes from a newer JDK
  ("Unsupported class file major version 70" on JDK 26), and macOS may default to
  one. `package/android.sh` pins JDK 21 when it is installed.
- **`local.properties` is machine-specific** and not committed; the script writes
  it from the standard SDK location when it is missing.
- **`gomobile bind` needs `golang.org/x/mobile` in the module** (`go get -tool
  golang.org/x/mobile/cmd/gobind`), which is why it appears in `go.mod`'s tool
  directive.
